# Zylo Phase 10: Deploy Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The API server gets ready to deploy. On SIGTERM it stops cleanly: every browser reconnects on its own, to any server, with its seat kept. It talks WebSocket only. In production it logs one JSON line per entry. A scripted load test records real numbers, and a step-by-step guide covers deploying to Vercel, Railway, LiveKit Cloud and Clerk.

**Architecture:**
- **Logger.** `server/lib/log.js` is the server's one logger. Locally it prints the same readable text as today; with `NODE_ENV=production` it prints one JSON line per entry.
- **Planned stop.** `server/lib/shutdown.js` runs it, in order:
  1. Stop listening.
  2. Call the room handlers' `stop()`: timers end, AI calls abort, and an answer in progress posts `ai:failed`.
  3. Close every connection with `io.close()`. The browser sees `transport close` and reconnects; each socket's `disconnect` handler holds its seat in Redis.
  4. Wait up to 8 s for socket handlers still running, which the `on` wrapper now counts.
  5. Close Redis and Postgres, then resolve to an exit code.

  A 10 s watchdog bounds the whole stop. `server.js` runs this on SIGTERM or SIGINT and exits with the code.
- **WebSocket only.** Socket.IO runs WebSocket-only in the browser and on the server.
- **Load test.** `server/scripts/load-check.js` drives 20 simulated people across two in-process API servers. `lk load-test` covers video.
- **Deploy guide.** `docs/deploy.md` is the deploy walk-through.

**Tech Stack:**
- Server: Node 22, Express 5, Socket.IO 4.8.3 (engine.io 6.6.10) with `@socket.io/redis-adapter` 8.3, ioredis 5.11, pg 8.23, node:test.
- Web: Next.js 16, socket.io-client 4.8.
- Load test: LiveKit CLI `lk` 2.18.8 and `livekit-server --dev`.

## Decisions this plan makes where the spec is open

1. **`io.close()` is the call that hands people over. Verified in `node_modules` and by experiment** (socket.io 4.8.3, engine.io 6.6.10, socket.io-client 4.8.3):
   - `Server.close()` (`socket.io/dist/index.js:489`) does this, in order:
     1. calls `socket._onclose("server shutting down")` on every socket, which sends **no** DISCONNECT packet;
     2. awaits `nsp.adapter.close()`;
     3. calls `this.engine.close()` (engine.io `close()` → `clients[sid].close(true)` → `transport.close()` → `ws.close()`);
     4. then `this.httpServer.close(cb)`.

     **So `io.close()` closes the HTTP server too.**
   - `io.disconnectSockets(true)` → `socket.disconnect(true)` → `client._disconnect()` → `socket.disconnect()` for each socket, which **does** send a DISCONNECT packet. That is `io server disconnect`, and it turns the browser's reconnection off.
   - A scratch experiment, with a WebSocket-only server and client:

     | Server call | What the client saw |
     |---|---|
     | `io.close()` | `transport close`, `client.active === true` (it keeps retrying), `httpServer.listening === false` |
     | `io.local.disconnectSockets(true)` | `io server disconnect`, `client.active === false` |
     | `io.engine.close()` | `transport close`, but the HTTP server kept listening |
     | `httpServer.close()` alone | still connected: upgraded sockets are untouched |

   - The plan calls `httpServer.close()` first (spec step 1: nothing new while `stop()` runs), then `io.close()`. The second close inside `io.close()` finds the server already closed and resolves at once (3 ms in the experiment).
2. **A polling handshake is refused by engine.io itself.** `Server.verify()` (`engine.io/build/server.js:112`) returns `UNKNOWN_TRANSPORT` for a transport not in `opts.transports`, and `abortRequest` answers HTTP **400** `{"code":0,"message":"Transport unknown"}`. A polling-only client gets `connect_error` `xhr poll error`. Two consequences:
   - The web change must land with the server change: the browser's default transport list starts with polling, which this server now refuses (Task 2).
   - The socket test uses the harness, whose `Server` options mirror `server.js` the way its adapter options already do. Task 2 also boots the real `server.js` once to prove the same 400.
3. **`stop()` resolves once the answers it aborted have posted `ai:failed`.** Without this, `io.close()` closes the asker's connection before `answer()`'s `catch` runs, and people on the stopping server never hear `ai:failed`. A mutation of exactly this fails the Task 2 test. `room.js` keeps the in-flight `answer()` promises in a `Set`. Existing callers ignore the return value, so nothing else changes.
4. **The 8 s drain covers the handlers after the connections close** (the `disconnect` handlers' Redis writes, and anything else still running). The wait in `stop()` for aborted answers is not counted against it; the 10 s watchdog bounds both.

   `ponytail:` a connection whose far end has vanished keeps `io.close()` waiting until `ws` gives up on it (30 s). The watchdog turns that into exit code 1 at 10 s. The seats were already held by then, because the `disconnect` handlers run when the socket closes, not when the TCP connection ends.
5. **Text mode keeps today's `msg: message` shape.** The spec says both "msg, then any fields as `key=value`" and "the existing tests that capture log lines read the same". Those tests match `chat history failed: redis hiccup`, `AI nudge failed: AI provider answered 500` and `arguments[0]` `/join failed/`, and `multiServer` checks `startsWith('room sweep failed')`. So text mode prints:
   - an `err` field as `"<msg>:", "<err>"`, the same arguments `console.error('x failed:', err.message)` passes today;
   - then the other fields as `key=value`.

   No existing test changes. A failed socket handler keeps the message `socket <event> failed`, the text two negative assertions in `aiChat`/`aiNudges` match, and also carries the `event` field the spec asks for.
6. **Both modes write through `console`, looked up on every call.** `info` → `console.log` (stdout); `warn` → `console.warn` and `error` → `console.error` (both stderr), as the spec routes them. This keeps `t.mock.method(console, 'error')` working. The default instance is tested in two child processes (`NODE_ENV=production` and not), because it reads `NODE_ENV` when `lib/log.js` loads.
7. **`createLog` also returns its `base` object**, and every JSON line spreads it when it is printed. `server.js` sets `log.base.serverId` at the top of `main()`. The spec says `base` carries `serverId` "once it exists", and the default instance exists before `main()` runs. `serverId` is now made once at the top of `main()` and always, even without Redis, so the start line always has it. Fields whose value is `null` or `undefined` are dropped (for example `userId` on a socket that never signed in).
8. **`createRedis` and `createLimiter` keep their `log` parameter.** Their default changes from `console` to the shared logger, so their outage lines are JSON in production too. The move covers 25 direct `console.*` calls plus these two defaults (four lines); the spec estimated "about 24".
9. **`meeting ended` is logged inside `markEnded(meetingId, reason)`**, only when its `UPDATE` changed a row. Every end goes through `markEnded`: `host:end-meeting` → `host`, `endEmptyRoom` → `empty`, the idle clear → `idle`, the Postgres pass → `stale`. So each meeting logs once, even when two servers sweep it.
10. **A 500 in `app.js` logs `err.message` and `err.stack`.** Today it prints the whole error object, stack included. The stack is what finds the line, and it carries no request body.
11. **Signals.** Handling SIGTERM/SIGINT replaces Node's default exit, so `onStopSignal` ignores a second signal itself. The watchdog bounds the stop. Experiment: `npm start` forwards SIGTERM to `node server.js` and waits for it, and `node --watch` (`npm run dev`) forwards it to its child. So Railway's `npm start` and local Ctrl-C both reach the stop.
12. **`lk load-test` counts.** In lk 2.18.8, `--audio-publishers` are the same participants as `--video-publishers`, not extra ones. A local run with `--video-publishers 2 --audio-publishers 2 --subscribers 1` produced:
    - 3 participants: `*_pub_0` (2 tracks), `*_pub_1` (2 tracks) and one subscriber (0 tracks);
    - the subscriber received 4/4 tracks (2 audio, 2 video).

    So `--video-publishers 5 --audio-publishers 5 --subscribers 15` is the spec's 20 participants.
13. **The load check's hand-over is simulated, and honestly.** When a person's connection to server A drops with `transport close`, the script reconnects them to server B at once, as a load balancer would route the browser's own retry. A real browser first waits socket.io's reconnection delay (0.5–1.5 s), which the 10 s mark absorbs. The pass mark also requires every reason to be `transport close`: a browser that saw `io server disconnect` would not retry, so the simulation must not either.
14. **The load check's cost numbers are for the whole process.** Both servers and all 20 clients share the process (spec: "two API servers in one process"), so per-server RSS/CPU can't be separated. Redis commands per minute come from `INFO commandstats` and cover the whole Redis server. The script says both on its output line. It also prints a fifth mark, everyone heard `ai:done` exactly once, which is spec §5.2 step 3's requirement.
15. **Railway's stop window.** Railway's docs define `drainingSeconds` / `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` as "the time in seconds between when the previous deploy is sent a SIGTERM to the time it is sent a SIGKILL". They give no default; Railway's help threads say 0 or 3 s. The guide sets it to **15**, so the 10 s watchdog always fits.

    The guide also pins Node with `RAILPACK_NODE_VERSION=22`, because Railpack reads `engines.node` (`>=22`) as a range. If Redis's private hostname doesn't resolve, the guide's fix is `?family=0` on `REDIS_URL`: Railway's docs say ioredis looks up IPv4 only by default, which fails in legacy IPv6-only environments.
16. **Spec §5.2 says "throughout" for the speech reports**, so the load check sends `voice:activity` from the join through the planned stop.

Create `server/lib/log.js`:

```js
// The server's one way to log. JSON mode (production): one line per call,
// {"time","level","msg",...base,...fields}, for the host's log search. Text mode
// (anywhere else): what the server has always printed, msg, an error as "msg: message",
// then the other fields as key=value. Both write through console (info: console.log,
// so stdout; warn and error: stderr), looked up on every call, so a test that mocks
// console.error still sees the line. Fields left null or undefined are dropped.
// base: fields on every JSON line (server.js adds serverId once it has one). Text mode
// leaves it out: a local run is one server.
// ponytail: no level filter and no redaction. Callers pass ids and error messages, never
// chat text, questions, answers, tokens or keys (spec §4).
const PRINT = { info: 'log', warn: 'warn', error: 'error' };

function createLog({ json = false, base = {} } = {}) {
  const at = (level) => (msg, fields = {}) => {
    const kept = Object.entries(fields).filter(([, value]) => value != null);
    const print = PRINT[level];
    if (json) {
      console[print](JSON.stringify({ time: new Date().toISOString(), level, msg, ...base, ...Object.fromEntries(kept) }));
      return;
    }
    const rest = kept.filter(([key]) => key !== 'err').map(([key, value]) => `${key}=${value}`);
    if (fields.err != null) console[print](`${msg}:`, fields.err, ...rest);
    else console[print](msg, ...rest);
  };
  return { base, info: at('info'), warn: at('warn'), error: at('error') };
}

const log = createLog({ json: process.env.NODE_ENV === 'production' });

module.exports = { createLog, log };
```

Create `server/lib/shutdown.js`:

```js
const { log: defaultLog } = require('./log');

// The planned stop (spec §2): SIGTERM on a redeploy, or Ctrl-C. Everyone on this server
// moves to another one without losing their seat. It never exits the process: it
// resolves to the exit code (0 a clean stop, 1 if the whole stop overran watchdogMs), so
// tests and the load check can stop one of two servers in one process.
// handlers: registerRoomHandlers' result, or null when this server runs no rooms.
// redisClients: every Redis connection the server opened (the main one, the adapter's two).
async function shutdown(
  { httpServer, io, handlers, redisClients = [], db = null, log = defaultLog },
  { drainMs = 8_000, watchdogMs = 10_000 } = {},
) {
  const started = Date.now();

  async function stop() {
    log.info('shutting down');
    httpServer.close(); // no new connections; io.close() below resolves once the last one has gone
    // Heartbeat, sweep and grace timers stop and every AI call aborts. It resolves once
    // each answer it cut short has posted ai:failed, while its people here are still
    // connected to hear it.
    await handlers?.stop();
    log.info('shutdown: timers and AI stopped');
    // Closes every connection without a disconnect packet: each browser sees its
    // transport close and reconnects on its own, to whichever server takes it (an
    // "io server disconnect" would switch that off). Each socket's disconnect handler
    // stamps graceUntil on its seat in Redis, so the seat outlives this process.
    // ponytail: a connection whose far end has vanished holds io.close() until ws gives up
    // on it (30 s); the watchdog turns that into exit code 1 at 10 s, after the seats were
    // already held. Bound this wait on its own if that ever happens often.
    const closing = io.close();
    const handlersDone = await handlers?.drain(drainMs);
    await closing;
    log.info('shutdown: connections closed', { handlersDone });
    // Last, so the disconnect handlers above could still write. quit() lets pending
    // replies arrive; a connection that can't send it is cut instead.
    const quit = (client) => client.quit().catch(() => client.disconnect());
    await Promise.allSettled([...redisClients.map(quit), db?.close()]);
    log.info('shutdown: redis and postgres closed');
    log.info('shutdown complete', { ms: Date.now() - started });
    return 0;
  }

  let timer;
  const watchdog = new Promise((resolve) => {
    timer = setTimeout(() => {
      log.error('shutdown timed out', { ms: Date.now() - started });
      resolve(1);
    }, watchdogMs);
  });
  const stopped = stop().catch((err) => {
    log.error('shutdown failed', { err: err.message });
    return 1;
  });
  const code = await Promise.race([stopped, watchdog]);
  clearTimeout(timer);
  return code;
}

// Runs stop() on the first SIGTERM (a redeploy) or SIGINT (Ctrl-C), then exits with the
// code it resolves to. Handling the signals replaces Node's own exit, so a second
// signal while stopping is ignored: the watchdog already bounds the stop.
function onStopSignal(stop, { target = process, exit = (code) => process.exit(code) } = {}) {
  let stopping = false;
  const handle = () => {
    if (stopping) return;
    stopping = true;
    stop().then(exit);
  };
  target.on('SIGTERM', handle);
  target.on('SIGINT', handle);
}

module.exports = { shutdown, onStopSignal };
```

```js
  const ids = Array.from({ length: PEOPLE }, (_, i) => `u${String(i).padStart(2, '0')}`);
  for (const id of ids) await insertUser(db, { id, email: `${id}@zylo.test`, name: `Person ${id}` });
  await insertMeeting(db, { id: MEETING_ID, hostId: ids[0], maxParticipants: PEOPLE });
  const provider = await startFakeAi(t, aiAnswer(['The launch ', 'moves ', 'to ', 'Friday.'], { gapMs: 100 }));
  const ai = createAi({ baseUrl: provider.baseUrl, apiKey: 'test-key', model: 'test-model' });
  const a = await startOwnRoomServer({ serverId: 'load-a', ai, graceMs: GRACE_MS });
  const b = await startOwnRoomServer({ serverId: 'load-b', ai, graceMs: GRACE_MS });
  await settle(200); // let both adapters' subscriptions land

  const wallStart = Date.now();
  const cpuStart = process.cpuUsage();
  const callsStart = await redisCalls(redis);
  let rssPeak = process.memoryUsage().rss;
  const rssTimer = setInterval(() => {
    rssPeak = Math.max(rssPeak, process.memoryUsage().rss);
  }, 1_000);

  // Each person keeps what they heard: chat lines by text with the time, and ai:done count.
  const people = ids.map((id, i) => ({ id, onA: i % 2 === 0, heard: new Map(), done: 0 }));
  const listen = (person, client) => {
    person.client = client;
    client.on('chat:message', ({ text }) => person.heard.set(text, Date.now()));
    client.on('ai:done', () => {
      person.done += 1;
    });
  };
  const join = async (person, url) => {
    const client = connectClient(url, person.id);
    listen(person, client);
    await waitForEvent(client, 'connect');
    const asked = Date.now();
    const admitted = admittedWithin(client, 10_000);
    client.emit('meeting:join-request', { meetingId: MEETING_ID });
    return { admitted: await admitted, ms: Date.now() - asked };
  };

  // 1. Join: all 20 at once, 10 on each server.
  const joins = await Promise.all(people.map((person) => join(person, (person.onA ? a : b).url)));
  const seated = joins.filter((j) => j.admitted).length;
  const seatsHeld = (await b.store.listSeats(MEETING_ID)).length;

  // 4. Speech reports from everyone every 10 s, from here through the planned stop.
  let speechReports = 0;
  const speech = setInterval(() => {
    for (const person of people) person.client.emit('voice:activity');
    speechReports += people.length;
  }, SPEECH_EVERY_MS);

  // 2. Chat for 60 s: everyone sends a line every 5–10 s, and halfway everyone at once.
  const sent = new Map(); // text -> when it was sent
  const send = (person) => {
    const text = `${person.id} says line ${sent.size + 1}`;
    sent.set(text, Date.now());
    person.client.emit('chat:message', { text });
  };
  const chatEnds = Date.now() + CHAT_MS;
  await Promise.all([
    ...people.map(async (person) => {
      for (;;) {
        await settle(5_000 + Math.random() * 5_000);
        if (Date.now() >= chatEnds) return;
        send(person);
      }
    }),
    settle(CHAT_MS / 2).then(() => people.forEach(send)),
  ]);
  await settle(1_000); // the last lines land
  const delivery = [];
  let lost = 0;
  for (const [text, at] of sent) {
    for (const person of people) {
      const heardAt = person.heard.get(text);
      if (heardAt === undefined) lost += 1;
      else delivery.push(heardAt - at);
    }
  }

  // 3. Ask AI: one person asks, the fake AI streams, and everyone hears ai:done once.
  const allDone = Promise.all(people.map((person) => waitForEvent(person.client, 'ai:done')));
  const askedAt = Date.now();
  people[1].client.emit('ai:ask', { text: 'When does the launch move to?' });
  await Promise.race([allDone, settle(10_000)]);
  const answerMs = Date.now() - askedAt;
  await settle(500); // a second ai:done would have arrived by now
  const doneOnce = people.filter((person) => person.done === 1).length;

  // 5. Planned stop: server A stops as it would on SIGTERM. Its people's connections close;
  // a load balancer would send their browsers to B, so each reconnects to B at once (a
  // browser first waits socket.io's reconnection delay, 0.5–1.5 s by default).
  const moving = people.filter((person) => person.onA);
  const seqBefore = new Map();
  for (const person of moving) seqBefore.set(person.id, (await b.store.seatFor(MEETING_ID, person.id)).seq);
  const reasons = [];
  const rejoined = Promise.all(
    moving.map(
      (person) =>
        new Promise((resolve) => {
          person.client.once('disconnect', async (reason) => {
            reasons.push(reason);
            person.client.disconnect(); // its own retries would go to A, which is gone
            const back = await join(person, b.url);
            resolve({ ...back, at: Date.now() });
          });
        }),
    ),
  );
  const stopAt = Date.now();
  const exitCode = await shutdown({
    httpServer: a.httpServer,
    io: a.io,
    handlers: a.handlers,
    redisClients: [a.redis, ...a.pubsub],
    db: a.db,
  });
  const back = await rejoined;
  clearInterval(speech);
  const reseatMs = Math.max(...back.map((r) => r.at)) - stopAt;
  let kept = 0;
  for (const person of moving) if ((await b.store.seatFor(MEETING_ID, person.id))?.seq === seqBefore.get(person.id)) kept += 1;

  // 6. Cost. Both servers and all 20 clients share this one process, so its memory and
  // CPU time are the two servers' together, plus the clients'.
  clearInterval(rssTimer);
  const wallMs = Date.now() - wallStart;
  const calls = (await redisCalls(redis)) - callsStart;
  const cpu = process.cpuUsage(cpuStart);

  console.log(`\nZylo load check: ${PEOPLE} people, 2 API servers, one process. Node ${process.version}, ${os.cpus()[0].model}, ${os.cpus().length} cores, ${Math.round(os.totalmem() / 2 ** 30)} GB`);
  console.log(`Join     ${seated}/${PEOPLE} admitted, ${seatsHeld} seats held; join-request → admitted ${spread(joins.map((j) => j.ms))}`);
  console.log(`Chat     ${sent.size} lines × ${PEOPLE} people, ${lost} lost; send → receive ${spread(delivery)}`);
  console.log(`Ask AI   ai:done exactly once for ${doneOnce}/${PEOPLE}; question → last ai:done ${ms(answerMs)}`);
  console.log(`Speech   ${speechReports} voice:activity reports`);
  console.log(`Stop     shutdown() → ${exitCode}; disconnect reasons: ${[...new Set(reasons)].join(', ')}; ${back.filter((r) => r.admitted).length}/${moving.length} seated again, ${kept} in the same seat; last one ${ms(reseatMs)} after the stop`);
  console.log(`Cost     Redis ${calls} commands in ${(wallMs / 1000).toFixed(0)} s = ${Math.round(calls / (wallMs / 60_000))}/min (whole Redis server); process RSS peak ${Math.round(rssPeak / 2 ** 20)} MB; CPU ${(cpu.user / 1e6).toFixed(1)} s user + ${(cpu.system / 1e6).toFixed(1)} s system\n`);

  const p95 = percentile(delivery, 95);
  const handedOver =
    exitCode === 0 &&
    reasons.every((reason) => reason === 'transport close') && // a browser that saw anything else would not retry
    back.every((r) => r.admitted) &&
    kept === moving.length &&
    reseatMs < 10_000;
  const marks = [
    [`all ${PEOPLE} seated`, seated === PEOPLE && seatsHeld === PEOPLE],
    ['no chat line lost', lost === 0 && delivery.length > 0],
    [`95th-percentile chat delivery ${ms(p95)} < 200 ms`, p95 < 200],
    ['everyone heard ai:done exactly once', doneOnce === PEOPLE],
    [`the stopped server's ${moving.length} people seated again, seats kept, in ${ms(reseatMs)} < 10 s`, handedOver],
  ];
  for (const [name, ok] of marks) console.log(`${ok ? 'PASS' : 'FAIL'}  ${name}`);

  for (const person of people) person.client.disconnect();
  await a.cleanup();
  await b.cleanup();
  for (const fn of cleanups) await fn();
  await redis.quit();
  await db.close();
  return marks.every(([, ok]) => ok);
}

main().then(
  (passed) => process.exit(passed ? 0 : 1),
  (err) => {
    console.error(err);
    process.exit(1);
  },
);
```
