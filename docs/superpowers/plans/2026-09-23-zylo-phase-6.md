# Zylo Phase 6: Zylo Translator Convo (1-on-1 live translated captions and voice, zero cost)

## Context

This is Zylo's headline feature. Two people who share no language talk face to face.
- Each person sees **live captions**: the other person's words in the original language, with the translation in their own language.
- Each person **hears the translation spoken** in their own language, over the partner's real voice played quietly.
- It costs nothing to run: browser speech APIs, Chrome's on-device translator, a free translation API as the fallback, and browser voices.
- There are **no server-side AI or paid APIs.**

Phase 5 (PR #5, `phase-5-ui`) is open and not merged. Phase 6 builds on its "Mute for me" and `AudioSink` code, so it branches off `phase-5-ui` and gets rebased onto `main` once #5 merges.

### Decisions (from the user)
- **Audio:** the partner's real voice plays **low (25%)** and the translation is **spoken at full volume** as each sentence finishes. Each person can change this for themselves: *Low* (default), *Full* or *Off*.
- **Fallback translator:** **MyMemory's free API**, used only where no on-device translator exists.
- **Languages:** Hindi, Russian and English (the core pair from the brief), plus **Indian languages** (bn, ta, te, mr, gu, kn, ml, ur) and **major world languages** (es, fr, de, ar, zh, ja, pt): **18 in total**, all from one table.
- **A third person** opening a full convo gets **"This convo already has two people"**, with no queue.
- Video stays on. It's a ZyloRoom with 2 seats, and Phase 5's grid already fits 2 people.

## What each browser gets (researched, 2026-09)

| Capability | Chrome desktop | Edge | Chrome Android | Safari macOS / iOS | Firefox |
|---|---|---|---|---|---|
| Speech to text (Web Speech API) | ✅ on-device (139+, hi-IN and ru-RU language packs), otherwise cloud | ✅ cloud | ✅ cloud | ✅ (14.1+) | ❌ type instead |
| Recognize a given track: `start(track)` | ✅ 135+ | ✅ | ❌ | ❌ | ❌ |
| On-device translator (Translator API) | ✅ 138+, 53 languages (**not gu, ml, ur**) | ✅ 148+ | ❌ | ❌ | ❌ |
| MyMemory fallback | ✅ | ✅ | ✅ | ✅ | ✅ |
| Voices (`speechSynthesis`) | ✅ Google voices (hi, ru, es, fr, de, ja, zh, pt, …) | ✅ Online Natural voices | ✅ Google TTS (most Indian languages) | ✅ system voices (hi, ru, ar, …) | OS voices only |

**MyMemory limits:**
- 5,000 characters a day per IP with no key, which is roughly 6–8 minutes of the partner's speech.
- Each request carries **at most 500 bytes** of `q`. Devanagari is 3 bytes per character, so about 160 Hindi characters fit.
- Running out is signalled by `quotaFinished` in the response.

The hybrid translation rule (below) means a **desktop + phone pair uses MyMemory for nothing**. Only phone + phone pairs touch the quota.

## Architecture

```
Speaker's browser                                   Listener's browser
mic ─► SpeechRecognition (speaker's lang) ─► interim + final text
        │  (paused while this browser is speaking TTS: echo guard)
        ├─► own caption shown locally
        └─► if on-device Translator(myLang→partnerLang) is ready:
               attach translation
      socket `convo:caption` {id, text, lang, final, translation?}
                         │  server: seat check, translator mode, validation, rate limit
                         ▼
                  relay to the OTHER seat only ──────────►  caption feed (keyed by userId+id)
                                                             translation = attached one if it's in my lang,
                                                               otherwise my on-device Translator,
                                                               otherwise MyMemory (finals only, chunked, cached)
                                                             final + translated ─► TTS queue (my voice, in order)
                                                               while speaking: duck partner's audio to muted,
                                                               pause my SpeechRecognition
```

- **Each person captions their own speech.** It's the only approach that works on every browser with speech recognition, phones included, and it keeps captions tied to the mic: mic off means no captions.
  - On Chrome/Edge desktop, recognition takes the **LiveKit mic track** (`recognition.start(track)`). That track is already echo-cancelled against the partner's WebRTC audio, and it follows mute automatically.
  - Everywhere else it falls back to `start()` on the default mic.
- **Hybrid translation.** Whoever has an on-device translator does the work; MyMemory is the last resort.
  - The sender attaches a translation when it can make one on-device for the partner's language.
  - The receiver uses that attachment, or translates the text itself.
  - Interim (live) text is translated **only on-device**, because it's fast and free. MyMemory is used for final sentences only, to save quota.
- **Transport is Socket.IO** (`convo:caption`), not LiveKit data. It reuses the server-side checks chat already has: a seat check, identity taken from the seat, validation, and now a rate limit. It also keeps working if video fails. The LiveKit token has no data grant (`canPublishData` is dropped after screen-share permission updates anyway).
- **Echo and loop guards**, in three layers. A voice that loops back is the failure that would kill this feature.
  1. SpeechRecognition **pauses while this browser's TTS is speaking**, and resumes 400ms after it ends.
  2. On Chrome/Edge desktop, `start(track)` uses the echo-cancelled LiveKit track, so the partner's voice from the speakers is removed.
  3. `isEcho()` drops any final result that closely matches something this browser spoke in the last 8 seconds.

  The UI suggests headphones.
- **Order and latency.**
  - Captions are keyed by `(userId, utteranceId)`, so an interim result is replaced by its final.
  - The TTS queue speaks in utterance order. It waits up to 4s for a slow earlier translation, then skips voicing it (the caption still shows).
  - When 2 or more utterances are waiting, it speaks at 1.15×.
- **Targets:**

  | What | Target |
  |---|---|
  | Original caption appears | ≤ 0.5s |
  | Translated caption, on-device | ≤ 1.5s after the sentence ends |
  | Translated caption, MyMemory | ≤ 2.5s after the sentence ends |
  | Translated voice starts | ≤ 2s after the sentence ends |

## Server (TDD, every guard mutation-checked)

1. **`server/db/schema.sql`**
   - Add `mode TEXT NOT NULL DEFAULT 'standard' CHECK (mode IN ('standard','translator'))` to `meetings`.
   - Also add `ALTER TABLE meetings ADD COLUMN IF NOT EXISTS mode …`. There is no migration system; `server.js:29-37` runs this file at every boot.
2. **`server/lib/meetingRules.js` `validateCreateMeeting`**
   - `mode` must be `'standard'` or `'translator'`, and defaults to `'standard'`.
   - Translator forces `maxParticipants = 2` and `admission = 'auto'`, and rejects `scheduledFor`/`inviteEmails`. It's link-shared and instant.
3. **`server/lib/meetings.js`**
   - `mode` goes into the INSERT, `CARD_SELECT` and `toCard`, so `MeetingCard.mode` is set.
   - The token route needs no change: `ensureRoom` already caps LiveKit at `max_participants`.
4. **New `server/lib/captionRules.js`**, the twin of the web language table:
   - `CONVO_LANGS`: the 18 codes.
   - `validateCaption({id, text, lang, final, translation})`:
     - `id` matches `/^[a-z0-9-]{1,32}$/`.
     - `text` is trimmed, with 1–500 characters.
     - `lang` is in `CONVO_LANGS`.
     - `final` is a boolean.
     - `translation` is optional; its lang must be in the list and its text must be 1–1000 characters.
   - `allowCaption(state, now)`: a token bucket of 8 events/second with a burst of 12 per socket. It's the first rate limit in the codebase, marked `ponytail:` (in memory, per socket).
5. **`server/lib/room.js`**
   - `loadMeetingMeta` selects `mode`.
   - `meeting:join-request` accepts an optional `lang`. It's validated against `CONVO_LANGS`, stored on the seat, and ignored for standard meetings.
   - **When a translator meeting is full**, the server emits `meeting:denied {reason:'full'}` instead of `enqueue`. The host's seat stays reserved, as it is today.
   - `broadcastPresence` adds `lang` to each person.
   - New `convo:set-lang {lang}` updates the seat and rebroadcasts presence.
   - New `convo:caption`, following the chat handler's pattern (room.js:252-265):
     1. Check the seat and that `seat.socketId === socket.id`.
     2. Check `meta.mode === 'translator'`.
     3. Run `allowCaption`, then `validateCaption`.
     4. `socket.to(roomChannel)` emits `{ userId, name: seat.name, ...clean, ts }`. The sender never gets its own caption back.
   - `server/lib/seats.js`: `tryTakeSeat` keeps a `lang` field on the seat record.
6. **Tests** (`server/test/`, using the `roomHarness` / `seat()` helpers):
   - rules unit tests
   - create route: translator forces 2 / auto
   - a third person gets `full` (not `waiting`)
   - presence carries `lang`
   - caption relay goes to the other seat only
   - forged `userId`/`name` are ignored
   - lobby, replaced and stale sockets can't send
   - standard meetings drop captions
   - bad payloads are dropped
   - the rate limit drops the excess
   - **a drift guard**: the server `CONVO_LANGS` equals the codes parsed out of `web/lib/convo-languages.ts`

## Web

### Pure modules
These have zero local imports and `node --test` tests, and every guard is mutation-checked.
- **`web/lib/convo-languages.ts`**: one row per language with:
  - `code`, `name`, `nativeName`
  - `stt` (a BCP-47 tag such as `hi-IN`, `cmn-Hans-CN`, `ar-SA`)
  - `onDevice` (the Translator API code, or `null` for gu, ml, ur)
  - `mymemory` (e.g. `zh-CN`)
  - `dir` (`rtl` for ar and ur)

  It also has `languageFor(code)` and `defaultLanguage(navigatorLanguages)`.
- **`web/lib/caption-feed.ts`**: a reducer over `{userId, id, text, lang, final, translation?}`. Interim results replace in place, finals commit, translations attach later, and it keeps at most 200 lines. Selectors give `latestFor(userId)` (the subtitle) and `transcript()`.
- **`web/lib/translate-chain.ts`**:
  - `chunkForMyMemory(text, 450)` splits by UTF-8 bytes at sentence, then word boundaries, and never cuts a surrogate pair.
  - `parseMyMemory(json)` returns `{text} | {quota} | {error}`.
  - `translateVia(engines, text, from, to)` runs the chain: same language returns the text unchanged, then on-device, then MyMemory, then `{failed}`. The engines are injected so tests use fakes.
  - It keeps a 200-entry LRU cache.
- **`web/lib/speech-policy.ts`**:
  - `onRecognitionEnd(reason, attempt)` returns `{restart, delayMs, notice}`:
    - `no-speech` / `aborted` / a normal end: restart immediately.
    - `network`: back off 1, 2, 4, then at most 10 seconds.
    - `not-allowed` / `service-not-allowed` / `language-not-supported` / `audio-capture`: stop, with a notice.
  - `isEcho(text, recentSpoken, now)` compares normalized text and checks containment within 8s.
- **`web/lib/voice-pick.ts`**:
  - `pickVoice(voices, sttTag)`: an exact tag match first, then a language-prefix match. It prefers "Google" or "Natural" voices, then a local match.
  - `splitForSpeech(text, 180)`: works around Chrome's cut-off on long utterances.
  - `speechRate(backlog)`.
- **`web/lib/convo-support.ts`**: capability detection with the globals injected, so it can be tested. It reports:
  - speech: `on-device-ready`, `on-device-downloadable`, `cloud` or `none`
  - translator: per language pair
  - voice: per language
  - whether `start(track)` is supported

### Hooks
These are verified live, not unit-tested. The logic that could be wrong lives in the modules above.
- **`web/lib/use-speech-captions.ts`** owns SpeechRecognition:
  - Settings: `continuous`, `interimResults`, `lang = stt`.
  - `processLocally = true` when available.
  - It calls `start(localMicTrack)` when supported; otherwise `start()`.
  - The restart loop follows `speech-policy`.
  - It's enabled only when the mic is on, the room is connected and TTS isn't speaking.
  - Interim results are throttled to 4 per second.
- **`web/lib/use-convo-translation.ts`**:
  - Keeps the on-device `Translator` instances per pair, with download progress through `monitor`.
  - `create()` runs from a click, because it needs user activation.
  - Runs MyMemory through `fetch` with `quotaFinished`, which sets a "daily limit reached" state for the session.
  - Supports the optional `NEXT_PUBLIC_MYMEMORY_EMAIL` (`de=`). It's off by default: with it set, every user shares one 50,000-a-day pool.
- **`web/lib/use-speech-output.ts`**:
  - Holds the `speechSynthesis` queue, loads voices on `voiceschanged`, and runs `unlock()` inside the Join click (iOS and Chrome need a user gesture for speech).
  - Exposes a `speaking` flag.
  - Calls `cancel()` on unmount.
- **`web/lib/use-translator-convo.ts`** ties it together:
  - Local captions go to `useMeeting.sendCaption`.
  - Remote captions arrive through the new `useMeeting(code, { onCaption })` option.
  - It feeds the caption reducer, the translation chain, the TTS queue, and the duck and pause signals.
- **Existing files:**
  - `use-meeting.ts`: add `lang` to `meeting:join-request`, plus `sendCaption`, `setConvoLang`, `onCaption` (held in a ref), and the new `full` denial reason.
  - `use-livekit-room.ts`: expose `localMicTrack` (the `MediaStreamTrack` from the mic publication) for `start(track)`.

- **`web/app/layout.tsx`**: set Plus Jakarta Sans to `subsets: ['latin','cyrillic-ext']` and `fallback: ['system-ui','sans-serif']`. Today the font stack has no generic family, so Russian or Hindi captions fall back to a serif font.
- **`web/components/dashboard-view.tsx`**: a 4th card, **Zylo Translator Convo**, linking to `/zylo-translator-convo`.
- **New `web/app/zylo-translator-convo/page.tsx`**:

  - **Start convo** POSTs `/meetings {title:'Translator Convo', mode:'translator'}` and routes to `/zylo-translator-convo/[code]`.
- **New `web/app/zylo-translator-convo/[code]/page.tsx`** renders `<MeetingRoomFlow code>`. The flow takes `meeting.mode` from pre-join. `/m/[code]` also works for a translator meeting.

- **`meeting-room-flow.tsx`**: `DENIED_COPY.full`, and it passes `mode`/`lang` through.
- **`room-shell.tsx`, translator mode:**
  - A **Captions** tab, the default, is added before ZyloChat and People. The ControlBar chat button opens Captions, so the 320px bar budget is untouched.
  - `VideoStage` gains a **subtitle overlay**, which only renders in translator mode.
- **New `web/components/subtitle-overlay.tsx`**:
  - Sits at the bottom of the stage and shows the partner's latest line: the translation large, the original small.
  - Uses `aria-live="polite"`, `dir="auto"` and `lang` on each line.
  - The caption doesn't change size between interim and final text (skeleton text), so the layout doesn't jump.
- **New `web/components/captions-panel.tsx`**:
  - A transcript with both languages and a "Type instead" composer, which sends a final caption. That's Firefox's path, and the path for noisy rooms.
  - Settings: **I speak** (sends `convo:set-lang`), **Read translations aloud** (on by default), **Partner's voice: Low / Full / Off**.
  - Banners:
    - "Download Hindi→Russian translation (one time)", when the pair is downloadable (needs a click)
    - "Free translation limit reached today, showing original text"
    - "Captions paused: reconnecting"
    - "Use headphones to avoid echo"
- **`video-stage.tsx` `AudioSink`**: add a `volume` prop, re-asserted by the existing `volumechange` listener, alongside `muted`. Partner volume is *Low* 0.25, *Full* 1 or *Off* muted, and it's muted while TTS speaks. iOS ignores `volume`, so *Low* acts as Full there and only the during-speech mute applies; this gets a `ponytail:` note.
