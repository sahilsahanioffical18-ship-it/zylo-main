# Zylo Phase 5 — UI polish, a video grid that fits the room, chat toast, "Mute for me"

## Context

Phase 4 is merged (`origin/main` @ `e202a92`). The user's new Phase 5 is a UI phase. It replaces the old "hardening/deploy" Phase 5, which moves to Phase 7. Phase 6 (Translator Convo) is planned separately, after this one.

The main complaint: **tiles don't adjust to how many people are in the meeting.** Today [video-stage.tsx](web/components/video-stage.tsx) uses a fixed `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` grid of 16:9 tiles inside a stage that can scroll:
- One person on a laptop gets a tile a third of the width.
- Two people on a phone get two thin strips.
- Twenty people scroll.

The room is also `min-h-dvh`, so the page grows and the control bar gets pushed off-screen. Below that:
- The control bar has 7 controls at 48px each (host), which wrap to 2–3 rows at 320px.
- ZyloLive shows on phones, where screen sharing can't work.

Also asked for:
- A toast when a ZyloChat message arrives.
- A local-only "Mute for me" in the People list.
- A design pass using **ui-ux-pro-max**, built with **ponytail** laziness.

Outcome: the room fills the viewport at every width from 320px to 1440px+, with tiles resized to the number of members, and nothing scrolling sideways.

**Design source of truth:** [design-system/zylo/MASTER.md](design-system/zylo/MASTER.md) and `pages/meeting-room.md`. They were written in Phase 1, and Phase 5 does not regenerate them. The rules that apply here:
- 44px minimum touch targets with 8px spacing.
- 150–300ms CSS transitions only.
- `prefers-reduced-motion` respected.
- Visible focus states.
- No horizontal scroll.
- `dvh`, not `vh`.
- Lucide icons.
- Toasts auto-dismiss in 3–5s.

**No server changes in Phase 5.** Everything is in `web/`.

## Task 2 — Video grid that fits the member count (the core of the phase)
**New** `web/lib/stage-layout.ts`: a pure module with no local imports, like `speaker-order.ts`.
```ts
export function fitGrid(count, width, height, gap): { cols; tileWidth; tileHeight; scroll }
```
- Try every column count `cols = 1..count`, with `rows = ceil(count/cols)`.
- Cell size is `(width-(cols-1)·gap)/cols × (height-(rows-1)·gap)/rows`.
- Shrink the tile inside the cell so its aspect ratio stays between **3:4 and 16:9**. The video is `object-cover`, so it crops instead of letterboxing.
- Keep the column count with the **largest tile area**. This one best-fit rule handles portrait phones, landscape tablets and desktops without a table of breakpoints:
  - Two people on a portrait phone stack vertically.
  - Two people on a laptop sit side by side.
  - Twenty people on desktop get a 5×4 grid.
- **Floor:** if the best tile is under `MIN_TILE_WIDTH` (120px), fall back to `floor((width+gap)/(120+gap))` columns of 16:9 tiles with `scroll: true`. This only happens with lots of people on a small phone, and it gets a `ponytail:` note about the limit.
- `count = 0`, or a size of zero, returns 1 column and no NaN.

**New** `web/lib/stage-layout.test.ts` covers: 1 person on desktop fills the stage; 2 people portrait stack; 2 people landscape side by side; 4 people make 2×2; 20 on desktop make 5 columns; 20 at 288px wide scroll; 0 people or a 0 size are safe.

**[video-stage.tsx](web/components/video-stage.tsx)**, grid branch:
- Measure `<main>` with a `ResizeObserver` inside `useLayoutEffect`, reading `getBoundingClientRect` first so there is no first-frame flash.
- Render `grid-template-columns: repeat(cols, tileWidth px)`, centered, with `overflow-y-auto` only when `scroll` is true.
- `Tile` gets an optional `style={{width, height}}`. It keeps `aspect-video` when no size is given, so the presenting filmstrip is unchanged.
- The "Connecting video…" line moves out of the grid into an absolute overlay, so it never counts as a cell.

**[room-shell.tsx](web/components/room-shell.tsx):** change the root from `min-h-dvh` to `h-dvh overflow-hidden`. The stage then has a fixed height to fit into, and the control bar stays pinned at the bottom.

## Task 5 — ZyloChat toast
**New** `web/lib/chat-toast.ts` + `.test.ts`:
- `shouldToast(msg, selfUserId, chatVisible)` returns false for your own messages and when chat is on screen.
- `toastPreview(text, max = 80)` trims at a word boundary and adds `…`.

In [room-shell.tsx](web/components/room-shell.tsx), an effect keyed on `messages.at(-1)`:
- It's keyed on the last message, not the count, because `use-meeting` slices the list at `MAX_MESSAGES`, so the length stops changing once the cap is reached.
- A ref records the last message at mount, so a remount doesn't toast old history.
- `chatVisible = tab === 'chat' && (sheetOpen || matchMedia('(min-width:1024px)').matches)`, the same pattern `openPanel` uses.
- The toast call:
  ```ts
  toast(name, { id: 'zylochat', description: toastPreview(text), duration: 4000, position: 'top-right', action: { label: 'Open', onClick: () => openPanel('chat') } })
  ```
  - The fixed `id` means a burst of messages replaces one toast instead of stacking.
  - Sonner v2 supports a per-toast `position`; `top-right` keeps it off the room title and the control bar.
  - No new dependency: `sonner` is installed and `<Toaster>` is mounted in [layout.tsx](web/app/layout.tsx).
